# Offer optional Bootstrap Import for existing Pinterest saves

PinRef offers an explicit, skippable Side Panel flow for selecting pre-existing Pinterest saves to import. Pinterest native Save remains the only automatic capture trigger during browsing; Bootstrap Import is the deliberate, user-confirmed exception needed to avoid presenting established Pinterest users with an empty, forward-only library. It does not introduce a general Add action for the current Context Pin.

Revised on 2026-09-30: Side Panel ownership replaces the previous Dashboard-owned flow for both first-use onboarding and repeated imports. Choosing a source from a separate Dashboard makes the relationship to the visible Board or individual Pin unclear. Keeping Import beside Pinterest makes the active page the explicit source and lets the user watch the scan without switching workspaces.

Import candidates do not count as References until selected and committed locally. Import deduplicates existing References, never stores or synchronizes Pinterest Boards, records the actual PinRef import time instead of inventing an original Pinterest save time, and reports successes, duplicates, and retryable failures separately.

The import is repeatable from the Side Panel rather than restricted to one onboarding run. Pinterest Boards may organize or filter candidates during the active import session, but that context is discarded afterward and never enters Reference data or search.

Each Import session requires the user to keep a Pinterest Saved or Board surface open. PinRef may scan content that this active surface can load, but completion means only that the current scan reached a reliably identifiable end; interruption produces a partial result rather than an account-wide completeness claim. Re-running Import discovers candidates and duplicates without mirroring Pinterest removals or mutations into the PinRef Library.

MVP supports the Saved Pins collection at `/<account>/_pins/` and one concrete Board as separate Import surfaces; it never silently traverses multiple Boards as an account-wide crawl. Pinterest's `/<account>/_boards/` profile view and `/pin/<id>/` individual Pin page are not Import surfaces. After an explicit Start Import action, PinRef may automatically scroll the open foreground Pinterest tab to load the selected surface. Cancel, navigation, tab closure, loss of foreground reliability, or loss of reliable Pin identity stops the scan and preserves a partial session.

Before the first Import, PinRef explains that it reads the open Pinterest surface, may scroll it, stores selected PinRef data locally, uses Board names only during the session, does not modify Pinterest, and relies on revocable Chrome permission. Each later Start Import action is the explicit session trigger. PinRef should prefer `activeTab`; if validation shows that it cannot support the Side Panel, SPA, and scan lifecycle reliably, the Extension may request optional Pinterest-only host access at Import time and retain it until the user revokes it. It must not broaden this fallback to all-sites access.

The Side Panel owns every Import session. Clicking the extension action opens the browser-native Side Panel. Before Start, the panel identifies the current active tab as Saved Pins (`/<account>/_pins/`), a concrete Board, an individual Pin (`/pin/<id>/`), or an unsupported page, and displays the verified collection source type and URL for Import. A Board name may appear only when verified from that surface; a browser tab title is not a trustworthy Board name or Pin count. Start binds the session to that exact tab and surface; it never selects a different tab or guesses a Board from a Pin. An individual Pin detail or close-up is a Context Pin surface, not a collection Import Surface. Pinterest Home and individual Pin pages show This Pin; Search, profile Boards (`/<account>/_boards/`), ambiguous pages, and non-Pinterest pages show an idle guide. None of these can start an import. On a non-Pinterest page, the guide directs the user to open Pinterest.

Disclosure, explicit Start, scanning progress, Stop and review, candidate review, all-or-part selection, commit, Retry, results, and Done or Dismiss all remain in the Side Panel. Review defaults to no selection. The Pinterest page stays beside the panel, and scan completion never opens or focuses Dashboard. Dashboard owns the committed Library and its management; any Import guidance there directs users to open the intended Pinterest collection and its Side Panel, without a tab picker or an Import execution flow. Pinterest receives no PinRef overlay.

Interacting with the Side Panel within the same browser window does not count as switching away from the bound Pinterest tab. Before Start and while scanning, the panel asks the user to keep that Pinterest tab and collection page open and unchanged. Tab activation, navigation to another surface (including opening a Pin close-up), window focus loss, panel closure, or permission loss nevertheless pauses an active scan and preserves a Partial session. Reopening the panel never resumes automatically. A paused session retains its original source label; switching tabs must not relabel or retarget it. Resume requires that original tab and surface to be active, then rescans from the top. Candidate review uses the session's recorded source, not the currently displayed Pinterest page.

The Side Panel lists unfinished Import Sessions with their recorded source, state, and candidate count. Choosing one changes only which session the panel shows; it never changes the scan binding or starts a scan. A Partial session can be reviewed and its observed candidates imported while another Pinterest page is active, provided the panel clearly identifies the original source. Resume requires the original tab and exact surface. If that tab has closed, reopening the same URL in a new tab does not rebind or resume the old session: the observed candidates remain reviewable, and a new scan in the new tab starts a separate Import Session.

On Saved Pins or a Board surface, the Side Panel shows Import and prioritizes an unfinished session bound to the active tab and exact collection surface. On Pinterest Home or an individual Pin page, it shows This Pin. Unsupported pages show an idle guide. Unfinished Import Sessions remain discoverable in every state without manual This Pin / Import tabs. If no Import Session matches, Import shows the current source and session list without starting or resuming a scan. Each entry and review header retains its original verified source label or URL. The user may explicitly choose a different session for review, including one whose tab has closed; navigation to another page restores that page's state without changing the session's binding or selection.

Resume does not trust DOM nodes or a stored scroll position. It rescans the same surface from the top and merges observations into the existing Import session by reliable Pin identity. Already observed candidates are not duplicated, and existing References remain duplicate results rather than new commits.

Only one scan may be active per browser profile, although multiple Import sessions may remain paused and resumable. Starting another scan requires the current scan to pause or cancel so tab focus, automatic scrolling, and candidate ownership stay unambiguous.

The Side Panel must not silently replace an active scan when the user opens another Board or Saved Pins tab. It identifies the running session and requires an explicit Stop & review or pause before Start is available on another surface. Selection in a reviewing session remains stored with that session when the active Pinterest page changes; the page change neither clears the selection nor rebinds its source.

An unfinished Import session may retain a Board name locally only as temporary session context across browser restarts. Complete or Dismiss deletes that Board context; it never becomes Reference data, a Library field, or searchable Board state.

An active Reference is a duplicate, repeated observations of the same reliable Pin identity merge into one candidate, and a Trashed Reference is reported as `In Trash`. Import never creates a second Reference or restores a Trashed Reference; recovery remains an explicit Trash action.

A reliable end-of-surface signal may mark a scan complete. A heuristic plateau without such evidence is `Unable to confirm completion`: observed identity-known candidates remain valid, while the session remains partial and resumable rather than being guessed complete or discarded.

Any Saved or Board surface the user can normally open, including secret and collaborative Boards, may be scanned under the same rules. PinRef describes the results as Pins observed on that surface, not necessarily Pins personally saved by that user. Board type is not retained on References or as persistent Library data.

Scan completion moves the Import session to candidate review; it does not end the session. After selected items resolve to imported, duplicate, or In Trash with no outstanding failures, Done completes the session and deletes its candidates and temporary Board context. Failed local writes keep the session open for Retry or Dismiss, but do not permit a further scan of that session after Import selected began. Dismiss deletes remaining session data without rolling back References already committed.

Before local import begins, a Partial session in review may Resume on its original active tab and surface. Rescanning merges by Pin ID and retains the user's existing selection; newly discovered candidates remain unselected. Once Import selected begins local writes, that same session cannot Resume a scan. While a scan is active, Stop & review is a single explicit action: it stops auto-scrolling, retains observed candidates, and enters review marked Partial without claiming the collection was completely scanned.

Import selected confirms a bounded set of candidate Pin IDs. Closing the Side Panel during local writes does not cancel those confirmed writes: processing continues, and each result is persisted so reopening the panel shows imported, duplicate, or retryable failed outcomes. Worker interruption must not silently discard an unresolved item or duplicate a committed Reference; the same operation identity is used for recovery.

Immediately before each selected candidate's local commit, PinRef checks current Library and Trash membership. If another Capture Attempt or Import has already committed that Pin, the candidate becomes Duplicate; if it has moved to Trash, it becomes In Trash. Neither result creates a second Reference or restores one. Revoking Pinterest permission after Import selected does not cancel confirmed local writes because they use previously observed Pin identities and no longer read Pinterest; revocation does stop an active scan and prevents Resume until access is available again.

An observed item without reliable Pin identity is skipped rather than becoming a URL-only candidate or anonymous failure. The scan summary reports how many items were skipped because identity could not be confirmed.

A scan with no identity-known candidates still shows a Partial review and its observed and skipped counts, with Resume when the original source is available and Dismiss as an explicit exit. Zero candidates never proves the collection was fully scanned. If every observed candidate is already Duplicate or In Trash, the user may choose Done without an empty Import selected operation. For a mixed review, Done may finish after selected items have resolved and no failures remain, even when some new candidates were left unselected. Before Done removes the session, the panel clearly states that unselected candidates and temporary Board context will be discarded; committed References remain in the Library. Leaving or closing the panel without Done retains the unfinished session for later selection.

Chrome Web Store submissions use a dedicated, non-personal Pinterest reviewer account with deterministic public, secret, collaborative, lazy-loading, and duplicate fixtures as applicable. Test instructions and fixture state are maintained alongside each submitted version so reviewers do not need to construct the scenario themselves.

A candidate with reliable scan-time Pin identity does not require live Pinterest revalidation before local commit. Candidate review starts with nothing selected and offers `Select all new`; active duplicates and `In Trash` results are visible but not selectable. Pinterest changes after observation do not cancel the user's explicit Import choice, while an unsuccessful local write remains a retryable Import failure.

Chrome Web Store disclosures conservatively describe the actual local handling of website content, user activity, and user-provided PinRef metadata. They state that PinRef does not read Pinterest passwords or authentication cookies and does not transmit Import data to a PinRef server. The product remains branded as PinRef, uses Pinterest only to describe compatibility, includes an independent-project non-affiliation statement, and does not imitate Pinterest branding.

Technical validation may narrow MVP to Board-only when Board scanning is reliable but Saved root or All Pins is not. Reliable identity with no reliable end signal supports only an explicitly partial `Stop and review` result. If even a Board surface cannot produce reliable Pin identity, Import is deferred rather than guessing from image URLs, text, DOM position, private endpoints, cookies, or intercepted network traffic.

Production implementation is gated on the existing Pinterest integration prototype demonstrating tab-and-surface binding, zero false Pin identities in controlled fixtures, safe cancellation and interruption, identity-based rescan merging, one active scan, duplicate and Trash classification, permission lifecycle, and reproducible completion, unconfirmed, failure, and Retry transitions. Wrong identity or cross-tab routing is a hard failure; Saved-root completeness and end detection may instead trigger the narrower fallbacks above.

Import from Pinterest is an MVP product requirement distributed as an open-source Manifest V3 Extension through the Chrome Web Store. Sideloading remains a development and review path, while Store review is the release gate for general-user distribution. Partial or interrupted imports remain in a resumable Import session with separate success, duplicate, and failure results; they do not enter Needs Attention, which remains reserved for native-Save Capture Attempts.
