# Coordinate Context Pin and Bootstrap Import in one Side Panel

The production Side Panel has This Pin and Import states because daily Pinterest Save work and repeatable collection Import share a browser window but have different sources and lifecycles. The states are not manual tabs: the active Pinterest Home or individual Pin page shows This Pin, Saved Pins or a concrete Board shows Import, and other pages show an idle guide. An explicit native Save may temporarily prioritize This Pin, and choosing an unfinished Import Session explicitly opens its review. Navigation to a different page returns to that page's state; the unfinished session remains discoverable and never changes source or loses selection. This avoids asking users to choose between two modes whose correct source is already known from the page.

A native Pinterest Save during an active Import scan pauses that scan as Partial and prioritizes the Capture Attempt's status. Pinterest Save can change the collection page, while Capture and Import may encounter the same Pin; preserving the observed candidates and resolving both paths against one Reference avoids false scan completeness and duplicate Library entries. Ambiguous Save evidence remains Save not confirmed under ADR-0001. Opening Dashboard from the Side Panel during a scan first warns that the tab change will pause the scan, then retains the Partial session for Resume on its original tab and surface.

The Side Panel uses the Dashboard Docked Inspector's title bar, preview, metadata, editing, and empty-state visual language while preserving Import's distinct scan and review controls. The Dashboard uses the complete Contact Sheet prototype interaction model against committed Local-first Library data. It opens All Pins after View Library, sorted by actual PinRef-added time without preselecting imported References. Search or Tag filter changes clear Gallery selection after protecting any Local Draft; sorting and layout changes retain selection. Waterfall keeps a stable gallery width when the Dashboard sidebar opens or closes, so balanced columns do not vertically relocate Pins. Layout preferences persist across Dashboard openings, and Light/Dark theme is shared with the Side Panel. Prototype sample records, simulated outcome controls, fixed counts, and placeholder destinations do not ship.

Revised on 2026-10-01: "Side Panel" here means the Docked Inspector, and the Dashboard Inspector is the same Inspector rather than a separate visual model. Placement and Dashboard hosting follow ADR-0013; Local Draft follows ADR-0014.

Revised on 2026-10-01 (Side Panel availability): the Side Panel is enabled only on Pinterest pages and the PinRef Dashboard. Chrome hides it on any other tab and shows it again on return; the extension action on other pages opens the Dashboard instead of an idle guide. Unsupported Pinterest pages still show the idle guide. A native Save on a related or feed card makes that card's Pin the Context Pin until the route changes, even on another Pin's page.

Revised on 2026-10-02 (availability reconciliation): Side Panel availability is per tab, and tab creation, activation and navigation each reconcile it, so leaving Pinterest hides the panel even when the tab switch is itself the event that wakes a suspended service worker. The global options stay enabled: disabling them would disable the one panel instance and leave `sidePanel.open` with nothing to open, so a tab the worker has not yet reached may briefly keep the previous tab's availability until the activation sync lands.
